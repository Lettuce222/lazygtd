# 公開 GitHub PR の監視

普段の起動では外部アクセスしない。仕事用データベースで監視を有効にしたいときだけ、
インストール済みの公式 GitHub CLI の絶対パスを指定する。

```sh
lazygtd --db /absolute/path/to/tasks.db --watch-github /usr/bin/gh
```

GitHub CLI は事前に `github.com` で認証する。公開リポジトリの読み取りに
必要な権限だけを使う。フラグは起動ごとに必要で、設定は DB に保存しない。
デモは外部アクセスせず、試したいときはデモの模擬確認を使う。

連絡待ちの項目の `watch` に、空白区切りで
`https://github.com/OWNER/REPO/pull/NUMBER` を登録する。末尾のスラッシュは
付けてもよいが、クエリ、フラグメント、追加パス、他のホストは自動監視の対象外。
対象外の URL が一つでも混じった項目は、自動で移動しない。リポジトリが公開と確認
できたときだけ PR の状態を読み取る。GitHub に送るのはリポジトリ名と PR 番号
（および GitHub CLI の認証情報）で、タスクのタイトル、本文、DB は送らない。

すべての URL が閉じている（マージ済みも含む）と同じ巡回で確認できた場合に限り、
その項目を「次の行動」に移す。監視中に項目を編集した場合は古い結果で移動しない。
存在しない PR、非公開リポジトリ、通信エラー、レート制限などで確認できない項目は
「連絡待ち」に残る。通常は90秒間隔で、確認不能が続くと最長15分まで間隔を延ばす。
アプリを閉じている間は動かない。別途確認した結果を扱う `watch-resolve` は従来通り。

## GitHub CLI を使わない場合

公式の `curl` があれば、認証せずに監視できる。WSL や Linux の例：

```sh
lazygtd --db /absolute/path/to/tasks.db --watch-github-curl /usr/bin/curl
```

この方式は GitHub のトークン、`.curlrc`、プロキシを使わず、リダイレクトを
追わない。公開 GitHub API への直接接続が必要なので、プロキシ必須のネットワークでは
使えない。未認証の API リクエストは GitHub 側の共有 IP 単位のレート制限を受ける。
制限中は項目を移動せず、間隔を延ばして再試行する。
